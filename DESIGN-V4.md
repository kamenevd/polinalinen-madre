# Мадре v4 — Дизайн-система «Живая книга»

> Утверждено Димой 20.07.2026 (мокапы: madre_v4_bakery_journal_concept,
> madre_v4_living_book_concept). Заменяет «Maison Levito» из DESIGN.md v3.

## Концепция

Приложение — не набор экранов, а **семейная книга рецептов, которая живёт**.
Каждый экран — страница или разворот. Никаких карточек-виджетов, никакого
material-дизайна. Материальность бумаги: типографские линейки, отточия,
штампы, ленточка-ляссе, загнутые уголки, библиотечный формуляр.

### Пять ключевых механик

1. **Мадре пишет дневник** — экран закваски это страница дневника от первого
   лица рукописным шрифтом. Записи генерируются из фазовой модели
   (SourdoughProfile): кормление → «меня покормили», пик → «я на пике! пеки
   со мной сейчас», голодная → «я проголодалась...». Это замена дашборду.
2. **Ляссе** — красная ленточка-закладка свисает с верха страницы, пока идёт
   выпечка. Тап → таймер. Это замена active-baking-card.
3. **Загнутый уголок = избранное** — вместо сердечек. Тап по углу строки
   оглавления подворачивает уголок (анимация).
4. **Формуляр выпечки** — история как библиотечная карточка в кармашке:
   дата (день римскими: 18.VII), что пекли, отметка рукой из поля notes.
5. **Дышащая страница** — на экране закваски вся страница едва заметно
   дышит: scale 1.000→1.004, период из фазы (пик 2с, голодная 1.5с, иначе 4с).
   Отдельного орба-виджета нет — есть маленькая пузырьковая виньетка-разделитель.

## Типографика

- **Заголовки/цифры**: FontFamily.Serif (Georgia). Огромные размеры — норма:
  masthead 44sp, таймер 88sp, номера глав 26sp.
- **Подписи-настроение**: Serif Italic 11-13sp («тесто спит. не будите его.»)
- **Служебные ярлыки**: SansSerif 9-10sp, letterSpacing 2-3sp, UPPERCASE
  («ОГЛАВЛЕНИЕ», «РЕЦЕПТ № 01», «ЖИВАЯ КУЛЬТУРА · ДЕНЬ 42»)
- **Рукописный (дневник, отметки формуляра)**: FontFamily.Cursive (системный
  generic — НЕ кастомный TTF, помним pitfall HarmonyOS).
- Тексты рецептов из PDF — Serif 14-15sp, БЕЗ изменений формулировок.

## Графический язык

- **Линейки**: двойная иерархия — жирная 2dp Espresso (главные разделы),
  волосяная 0.5dp Flour (строки).
- **Отточия**: пунктирная линия до значения в списках ингредиентов
  («тёплой воды ...... 285 г»). Значения — Crust, жирные.
- **Штампы**: рамка 1.5dp, скруглени 3-4dp, лёгкий поворот 2-4°, цвет по
  смыслу (В ПЕЧИ — Terracotta, ИСПЕЧЕНО — Sage). Никогда не заливка.
- **Талон**: рамка 1.5dp Espresso + полукруглые вырезы по бокам (перфорация).
- **Углы**: почти без скруглений — 4dp максимум (бумага, не пластик).
  Внешний контейнер экрана НЕ скругляется.
- **Иконки**: только существующие ic_*.webp + минимум outline. ZERO emoji.
  Поле emoji из recipes.json не рендерится.

## Экраны (8)

1. **Главная — «Первая полоса»**: masthead МАДРЕ + дата выпуска → строка от
   Мадре (последняя запись дневника, тап → дневник) → талон «В ПЕЧИ» (если
   выпечка активна) + ляссе поверх страницы → ОГЛАВЛЕНИЕ (11 глав: номер,
   название, время·сложность прописью, загнутый уголок избранного).
2. **Рецепт — «Разворот»**: РЕЦЕПТ № NN → название 32sp → курсивное
   описание → газетный подвал-статистика (ВРЕМЯ/ШАГОВ/СЛОЖНОСТЬ римской) →
   селектор «НА СКОЛЬКО ПЕЧЁМ» ×1..×5 (активный = залитая Espresso ячейка,
   «×3 семьи») → hero-фото как вклеенная фотокарточка → ингредиенты с
   отточиями (пересчитанные через RecipeScaler) → CTA «Начать выпечку».
3. **Таймер — «Ночная страница»**: ярлык ШАГ N ИЗ M → название шага курсивом →
   цифры 88sp по центру (формат hh:mm:ss при часах) → подпись-настроение →
   масло-алерт (рамка Terracotta, за 30 мин) → Пауза (outline) / Дальше (filled).
4. **Закваска — «Дневник культуры»**: ГЛАВА VII · ДНЕВНИК КУЛЬТУРЫ → «Мадре
   пишет:» → записи рукописью с таймштампами → пузырьковая виньетка →
   формуляр в кармашке → CTA «Покормить». Страница дышит.
5. **Кормление — «Новая запись»**: страница с линовкой, поля мука/вода как
   пропись, фото — вклеиваемая фотокарточка с уголками-держателями,
   место хранения — штамп КУХНЯ / ХОЛОД. (мокап — на согласовании)
6. **Готово — «Сургучная печать»**: круглая печать ИСПЕЧЕНО · 20.VII,
   колофон со статистикой, «вклейте фотокарточку». (мокап — на согласовании)
7. **Уведомления — «Записки на полях»**. (мокап — на согласовании)
8. **Настройки — «Выходные данные»**: колофон книги — имя закваски, интервал
   кормления, «тираж: одна семья», версия. (мокап — на согласовании)

## Cycle 1 — новые фичи «Живой книги» (24.07.2026)

#### Фича 1: «Пометы на полях» (MarginNotes)
Семья пишет заметки прямо на полях рецепта — рукописным шрифтом (Cursive),
привязка к конкретному рецепту. Как пометки на полях настоящей кулинарной книги.
- Данные: новая таблица Room margin_notes (recipeId, text, timestamp).
- UI: на RecipeDetailScreen под ингредиентами — секция «НА ПОЛЯХ» с
  существующими заметками (Cursive, поворот -1° для рукописности) и полем
  ввода (OutlinedTextField, transforms to Cursive on save).
- Каждая заметка — как помарка пером: Espresso цвет, Cursive шрифт.

#### Фича 2: «Архив глав» (DiaryArchive)
StarterDiaryScreen показывает только последнюю запись. Добавить возможность
пролистать все прошлые записи — как оглавление второго тома.
- На StarterDiaryScreen после текущей записи — волосяная линейка и секция
  «ПРОШЛЫЕ ГЛАВЫ»: список прошлых записей (дата римскими + первая строка),
  тап → разворачивает полный текст записи.
- Данные: SourdoughRepository уже хранит все feeding records. Генерировать
  тексты записей из SourdoughProfile для каждой прошлой feeding.

#### Фича 3: «Мадре советует» (MoodBookmark)
Вторая ляссе на главной — рекомендация рецепта под настроение закваски.
- Если закваска на пике → ляссе цвета Sage с текстом «Мадре советует:
  пеките сейчас!» → тап → рецепт, подходящий для активной закваски.
- Если голодная → Crust ляссе «Покормите меня сначала...» → тап → FeedingForm.
- Если пик давно прошёл → Terracotta ляссе «Я проголодалась...» → FeedingForm.
- Две ляссе не конфликтуют: baking-ляссе всегда Terracotta (как сейчас),
  mood-ляссе меняет цвет по фазе. Если baking активен — mood скрыт.

## Cycle 2 — новые фичи (24.07.2026)

### Фича 4: «Голоса семьи» (FamilyHand)
У каждого автора заметок на полях и записей дневника своя «рука»: лёгкая вариация

- Данные: table sealed_notes (id, recipeId, text, unlockAfterBakes, createdAt, unlockedAt)
- UI: кнопка запечатать на RecipeDetailScreen рядом с пометками на полях
- Wax seal механика уже есть в BakingCompleteScreen — переиспользовать
- Коммит: feat: time capsule — запечатанная записка на будущее

### Фича 6: «Растущий корешок» (SpineGrowth)
Иллюстрация корешка книги, которая визуально толстеет и приобретает потёртости.
- Thickness = bakeRecords count + feedingRecords count
- Canvas DrawScope рисование корешка сбоку
- Показывать на SettingsScreen как Состояние книги
- Коммит: feat: spine growth — корешок книги растёт с историей


## Cycle 3 — новые фичи (25.07.2026)

### Фича 7: Кляксы (InkBlot)
На страницах дневника и в формуляре появляются небольшие несовершенства.
Триггеры: отменённая выпечка — чернильная клякса рядом с записью.
Закваска в фазе HUNGRY — размытое пятно, будто дневник вели в спешке.
Canvas DrawScope, форма и положение — детерминированный seed от id события.
Не требует новых таблиц — подписывается на BakeRecord и SourdoughProfile.
Коммит: feat: ink blots — следы usage на страницах книги

### Фича 8: Экслибрис (Bookplate)
Титульная пластина владельца на экране настроек (Выходные данные):
орнаментальная рамка + вписанное вручную (Cursive) имя семьи.
Настраивается один раз при первом запуске или в настройках.
Компонент поверх существующего колофона.
Коммит: feat: bookplate — экслибрис семьи в выходных данных

### Фича 9: Сезонная глава (SeasonalEdition)
Оглавление и первая полоса реагируют на календарь.
Рядом с датой выпуска — сезонный ярлык (ЗИМНИЙ ВЫПУСК, ОСЕННЯЯ ГЛАВА).
Один рецепт получает отметку Глава сезона.
Данных не требует — вычисляется из LocalDate.now() и статического маппинга.
Коммит: feat: seasonal edition — книга живёт вместе с календарём

## Cycle 4 — новые фичи (25.07.2026)

### Фича 10: Затёртая страница (WornPages)
Часто печёные рецепты изнашиваются. После 3 выпечек — потёмнение края страницы.
После 7 — полупрозрачный отпечаток пальца в углу. После 15 — потёртость у корешка.
В оглавлении строки часто печёных глав тоже темнеют.
Чистый рендер: Canvas градиенты/текстуры с alpha от count(bakeRecords).
Ноль новых данных. Коммит: feat: worn pages

### Фича 11: Страница на просвет (LightPage)
Наклоняешь телефон — страница ловит свет: блик по бумаге + водяной знак на просвет.
На развороте рецепта — зеркальная тень заголовка следующего рецепта.
На дневнике — водяной знак MADRE · ЖИВАЯ КУЛЬТУРА · ДЕНЬ N.
SensorManager ROTATION_VECTOR -> alpha и смещение блика.
При отсутствии датчика — молчит. Коммит: feat: light page

### Фича 12: Правка от руки (HandwrittenEdit)
Пользователь рисует рукописные правки поверх текста рецепта.
Canvas drawing overlay на RecipeDetailScreen — поверх текста рецепта.
Сохраняется как bitmap в internal storage, привязка к recipeId.
Кнопка РЕДАКТИРОВАТЬ ОТ РУКИ переключает режим рисования.
Коммит: feat: handwritten edit

## Cycle 5 — общая семейная книга (25.07.2026)

Инфраструктурный цикл без новых декоративных механик. Он связал локальную
«Живую книгу» с семейным PocketBase и подготовил безопасную синхронизацию:

- `MadreApi` и модели записей PocketBase;
- `SyncRepository` + WorkManager с offline-first поведением;

- экспорт/поделиться без раскрытия приватных локальных данных.

Эти элементы не меняют сквозную нумерацию визуальных фич: следующая
пользовательская механика остаётся Фичей 13.

## Cycle 12 — ясная книга и живой таймер (03.08.2026)

Cycle 12 — не новый слой декора, а уборка интерфейса вокруг главных действий.

### Решения после multi-provider UX review

- **Слипшиеся страницы удалены из пользовательского потока полностью.** Они были задуманы как редкое книжное событие: скрытый жест «отлепить» открывал старую запись. На смартфоне это оказалось плохим обменом: жест конкурировал с правым скроллом, не был обнаруживаемым и выглядел как зависание. Эстетика не оправдала потерю предсказуемости. Исторические локальные данные не удаляются миграциями.
- **Фото — это контент, а не украшение.** Карточки на кормлении, завершённой выпечке и статистике открываются общим fullscreen viewer; закрытие работает через системный back и явную кнопку, чтобы не заставлять пользователя угадывать жест.
- **«Дальше» и «Отменить выпечку» разделены.** Отмена вынесена в отдельную спокойную зону и требует подтверждения; быстрый повторный тап не может случайно прервать выпечку.
- **Убраны/приглушены слои, которые закрывали текст и действия:** ink mirror, tracing paper и прочие декоративные overlays. Гербарий, конверт на будущее и записки на полях остаются удалёнными.
- **Мобильные правила:** ключевые цели от 48dp, ясные роли для TalkBack, один главный CTA на экран, минимум визуальных эффектов, честные offline/empty/error состояния.

### Уведомления

- Активная выпечка получает ongoing foreground notification: рецепт, этап, «шаг N из M», остаток и настоящая progress-line по времени всего рецепта.
- Tap ведёт в конкретную сессию, обновления тихие; завершение и отмена снимают строку.
- Сохранены напоминание кормления, окончание WAIT и предупреждение достать масло за 30 минут. Runtime permission запрашивается один раз и отказ не ломает локальную книгу.

### Acceptance criteria

- [x] StuckPages и перекрывающие пользовательский контент overlays отсутствуют в UX-потоке.
- [x] Фото открывается fullscreen на всех подключённых карточках.
- [x] Отмена выпечки отделена и подтверждается.
- [x] Ongoing progress notification обновляется foreground service и очищается при закрытии сессии.
- [x] Unit tests и lint проходят; APK собирается с `5.2.0-cycle12`.

## Cycle 14 — рецепт, ход выпечки и фотополка (2026-08-04)

### Фича 1: Своя закваска и честный масштаб рецепта
Имя закваски редактируется в настройках и используется во всех связанных текстах и напоминаниях. Выбор «на сколько печём» — единый источник масштаба: пересчитывает каждую ингредиентную величину, выход, подписи шагов и запись в историю. Времена технологических этапов не меняются молча от количества порций; если рецепт задаёт объём посуды или ограничение духовки, это показывается явно.

Acceptance:
- Имя закваски переживает перезапуск и корректно подставляется в дневник и уведомления.
- При смене количества порций ни один ингредиент, итоговый выход, шаг или запись о выпечке не остаётся со старым масштабом.
- Переключение порций покрыто unit-тестами на все типы ингредиентных ссылок; нет округления до нуля и дублей.

### Фича 2: Один ход выпечки и крупное уведомление
Экран выпечки показывает один канонический таймер текущего шага: «следующий шаг» не дублирует его отдельным таймером. Foreground-уведомление получает название текущего шага, живой обратный отсчёт, полный развёрнутый текст и тап ведёт в эту выпечку. Android управляет тем, разворачивать ли карточку в шторке, поэтому приложение не обещает насильно держать её раскрытой, но не прячет смысл в обрезанной строке.

Acceptance:
- Текущий шаг и его время берутся из одного состояния в экране и notification service; следующая стадия показывается только как название/контекст без второго отсчёта.
- Уведомление содержит видимый countdown, BigText без обрезания важного текста и корректно обновляется при pause/resume/finish.
- Отдельные напоминания не повторяются, а по тапу открывается нужная сессия; unit-тесты покрывают running, paused, last-step и zero-time.

### Фича 3: Месяц выпечки и фотоглавы
Статистика становится календарём текущего месяца: тепловая карта по дням показывает ритм выпечек. На полке каждая глава с выпечкой показывает последнее фото вместо цветного квадрата; тап открывает fullscreen viewer этой главы, в котором можно листать её снимки влево/вправо.

Acceptance:
- Heatmap показывает полный текущий календарный месяц, включая дни без выпечек, и не смешивает записи соседних месяцев.
- Плитка главы берёт последнее доступное фото, имеет честный fallback без фото и не декодирует всю галерею сразу.
- Fullscreen viewer открывается на последнем фото главы, листает только её фото в обе стороны, корректно обрабатывает границы, Back и broken-path.

### Правки после ревью Cycle 14 (2026-08-04)

Три независимых ревью нашли в фичах цикла то, что тесты пропустили. Решения,
принятые при исправлении:

- **Выход теста — это тесто, а не страница рецепта.** `RecipeScale.yieldGrams`
  считает вес ФИНАЛЬНОЙ секции: её собственные строки плюс то, что приносят
  ссылки. `all_of_section` приносит вес своей секции, «часть секции» — ровно то
  число, которое написано (у пиццы опары выходит 115 г, а в тесто идёт 100).
  Начинка и крем тестом не считаются: раньше синнабоны обещали два захода в
  духовку там, где заход один.
- **Свободный текст шага книга не разбирает.** В тексте пересчитываются только
  те числа в граммах и миллилитрах, которые рецепт уже задал строкой ингредиента
  (`RecipeScaler.scalableWeights`). «1 ст», «0,5 л», «оставьте 100 г опары» и
  прочая проза остаются как написаны: молча переписать их значило бы выдумать
  рецепт за Полину.
- **Лицо главы — последний ЧИТАЕМЫЙ снимок.** Проверка файла переехала из плитки
  в `ChapterPhotos`: удалённая из галереи свежая фотография больше не заслоняет
  собой десяток целых, а глава без единого читаемого снимка честно уходит в
  список попыток.
- **Открытая глава переживает пересоздание активити.** Полка хранит id рецепта,
  id главы и страницу viewer'а в `rememberSaveable`; системная «назад» закрывает
  сначала открытое поверх разворота.
- **Имя закваски, набранное до загрузки конфига, не пропадает** — оно ждёт в
  `StarterRenameQueue` и уходит в Room первым делом после загрузки.
- **Порции и таймер называют себя вслух** (contentDescription): «печём на 3
  семьи», «осталось 1 час 2 минуты» вместо «умножить на три» и «1:02:05».
- **Уведомления по ключу получили свою полку id** (3 000 000+): голый
  `key.hashCode()` мог попасть в id напоминания о кормлении или строки хода
  чужой выпечки — и снять её.

### Фича F: Крупная строка хода в шторке (BigBakingNotifications)

Строка хода была технически честной и визуально невесомой: заголовок —
название рецепта, под ним серый текст, под ним системная полоска. В
шторке, где рядом лежат мессенджеры с аватарами, она читалась как
служебное сообщение, а не как «у тебя в печи хлеб».

Что сделано — и чего сделано **не** было:

- Развёрнутая карточка — свой `RemoteViews`
  (`res/layout/notification_baking_progress.xml`) на бумаге: своя
  подложка `notification_paper`, чтобы чернила книги не оказались на
  чёрной панели системной тёмной темы. Палитра — та же, что в `Color.kt`,
  продублирована в `colors.xml` (`madre_notif_*`): RemoteViews не умеет
  читать Compose-токены, но второй палитры у книги нет.
- Шапка карточки — **имя закваски · название рецепта**. «Мадре · в печи»
  было бы неправдой у тех, кто закваску переназвал.
- Отсчёт в карточке — `Chronometer` в RemoteViews, а не текст: текст замер
  бы между обновлениями. Свёрнутая строка осталась системной, там тикает
  тот же хронометр. **Отменено в Cycle 21** (см. ниже): хронометр не
  останавливался на нуле и уходил в минус, обе карточки теперь свои и
  с готовыми цифрами.
- Ярлык: «пауза», когда стоит; «скоро», когда осталось меньше пяти минут.
  Без emoji и без второго числа.
- Полоска — по **времени** всей выпечки (`permille()`), не по номеру шага.
- Один отсчёт на выпечку: у следующего шага нет и не будет своего времени,
  в карточке он назван словами — «дальше · Формовка».
- **Кнопок в шторке нет.** «Пауза» и «Дальше» там означали бы, что ходом
  выпечки можно править вслепую, не глядя на страницу.
- **Раскрыть карточку силой нельзя** — программного способа у Android нет,
  и книга такого не обещает. Поэтому свёрнутая строка осмысленна сама по
  себе, а `BigText` остаётся заполненным: на прошивке, которая своей
  карточки не покажет, читается он.

Коммит: feat(notif): big progress card in the shade

### Фича G: Настройки в пять блоков (SettingsIaV2)

Колофон был одной лентой из четырнадцати строк подряд: имя, экслибрис,
почта и пароль, имя закваски, кормление, напоминания, оформление, тираж,
версия, корешок — и в самом конце ещё одно эссе про уведомления, спорившее

Теперь пять разделов, и ни одной новой настройки:

1. **Я** — ваше имя; экслибрис («как подписана книга») показывается только

2. **Закваска** — имя, «как часто кормить» человеческими словами (раз в

   телефоном» и кнопкой обратно, — отдельного эссе внизу страницы больше

5. **О книге** — журнал (выпечки · кормления) и версия.

Убрано: **«Тираж: одна семья»** — строка, не отвечавшая ни на один вопрос,
и рисованный корешок, споривший за внимание с числами рядом с ним.

Заодно из файла ушёл последний голый `Modifier.clickable` (hard rule №9):
строка настройки — это `bookAction`.

## Cycle 20 — maintenance: таймеры и уведомления (2026-08-12)

Maintenance после feature Cycle 19. Источник: жалобы на отрицательное время
в шторке и полоску, которая не доходит до конца на 00:00. Новых декоративных
механик нет.

### Фича 1: Хронометр до точного нуля (chrono-negative)

База system/RemoteViews Chronometer = точный конец шага (`stepEndsAtElapsed`),
а не `now + remaining*1000`. Тик ViewModel спит `min(1000, до границы шага)`
и приземляется **в** ноль. `formatRemaining`/`formatTimer` не печатают минус.

### Фича 2: Полоска шаг-локальная (progress-scope)

Полоска в шторке — доля **текущего** шага. Инвариант: `remaining == 0 ⇒
permille == 1000` на любом шаге. «шаг N из M» уже говорит про всю выпечку.

### Фича 3: Дорога из уведомления (no-content-intent)

«Время вышло» / масло / кормление открывают своё место в книге
(`EXTRA_SESSION_ID` / форма кормления). После записи кормления напоминание
снимается.

### Фича 4: Сервис без тихого FG-отказа (fgs-silent-drop)

Отказ `startForeground` → снять свои уведомления и `stopSelf`, не жить обычным
сервисом до ANR/kill.

### Фича 5: Одинаковый ноль на экране и в шторке (screen-never-says-done)

На нуле везде «время вышло», не «0:00» + «тесто спит». Порог «скоро» —
общая константа 300 с.

### DEFER

- полный перенос тика в foreground service (строка хода без активити)
- product-change nag-on-open для кормления


## Cycle 21 — residual после 6.4.0-maintenance20 (2026-08-12)

Тот же источник, что и у Cycle 20, и та же пара жалоб: **минус в шторке** и
**нечитаемая шторка в тёмной теме телефона**. Cycle 20 чинил базу хронометра —
минус пережил и подписанную сборку.

### Фича 1: Цифры в шторке рисует книга (shade-static-timer)

Системного хронометра больше нет ни в свёрнутой строке (`setWhen` +
`setUsesChronometer` + `setChronometerCountDown`), ни в развёрнутой карточке
(виджет `Chronometer`). Причина — в `docs/graveyard.md`: `Chronometer` не
останавливается на своей базе, а продолжает считать в минус, и подменить его
некому, когда OEM усыпил процесс, а уведомление оставил.

Цифры теперь готовая строка `BakingNotificationContent.timerText`, меняет её
только новое уведомление. Плата — застывшие цифры у замороженного процесса;
это честно и, в отличие от минуса, не выдумывает времени.

Свёрнутая строка от этого осталась бы без цифр вовсе, и остаток встал в неё
сам — **вторым**, сразу за названием шага: обрезание хвоста системой номер шага
переживёт, остаток нет.

### Фича 2: Бумага в обеих карточках (shade-dark-readable)

`notification_baking_compact.xml` — свёрнутая карточка на той же бумаге, в
бюджет высоты (шаг, остаток, тонкая полоска). `values-night` не заводится: он
перекрасил бы книгу целиком, а тёмной темы у неё нет (hard rule №3).

Бумага и чернила проставляются **из кода** поверх разметки
(`BakingShadeCards`): прошивки в тёмной теме перекрашивают уведомления, проходя
по уже инфлированному дереву, и подложка из XML теряется там первой.
`setColorized` не используется — полноцветная плашка спорила бы с бумагой.

На паузе ярлык встаёт **перед** шагом: стоящие цифры от идущих человек не
отличит никак, кроме слова (hard rule №8).

Системный шаблон остаётся заполненным (`title` + `contentText` + `BigText`) —
прошивка вправе не показать RemoteViews вовсе.

### Фича 3: notify только на изменение (shade-notify-on-change)

Слепки приходят раз в секунду всегда; на паузе и после конца шага карточка не
меняется, и пересылать её системе незачем. Сравнивается сам
`BakingNotificationContent` — то есть ровно то, что человек читает.

### DEFER (residual risk)

- перенос владения отсчётом в сам foreground service: пока процесс заморожен,
  цифры в шторке стоят. Честно, но не живо.

## Cycle 26 — факты вместо предсказаний

Для этого цикла база стартует от `v8`; миграционный путь только добавляет поля
пошагово `8 → 9 → 10`, без пересоздания и без перезаписи legacy-строк.

Дима одобрил выравнивание всей видимой подсказочной и редакционной речи с
буклетом Levito Madre. Первая полоса показывает срок только от личного
`intervalHours`:
- Гидратация в статусе и форме берётся только из фактически посчитанной
  `finalHydrationPercent`; старый `hydrationPercent` остаётся только для вывода
  строки в формуляре, если посчитанной ещё нет.
- «Кормление» и «Следующее кормление» показывают только фактический локальный

Кормление хранит три массы (закваска, мука, вода), автоматически считаемую

остаётся отдельным полем. Дневник использует короткие русские даты, ключевой

Видимая активная выпечка называется «Готовим». Компактный блок «Советы из
руководства» маркирует источник; рецептурные поля `recipes.json` в этом проходе
не меняются и ждут постраничной сверки Claude Opus.

### Кормление — расчёт (правка Cycle 26)

Форма кормления спрашивает ровно три массы: оставленная закваска (5–250 г,
по умолчанию 50), мука (10–500 г, 100) и вода (5–300 г, 50). У каждой —
своя карточка: подпись, крупное точное «N г», горизонтальный ползунок с
видимой шкалой (край / умолчание / край), кнопки «−5 г» и «+5 г» и набор
точного веса по нажатию на само число (весы редко показывают кратное пяти).
Ползунок нарисован книгой, а не Material: линейка в 2dp и засечка-бегунок со
скруглением 2dp, никакой пластиковой таблетки.
Стартерный стартовый комплект в подсказках — 2:1:2 (закваска:вода:мука), а
редактируемые удобные стартовые значения формы — 50/100/50. Они независимы: 2:1:2
остаётся отношением, а 50/100/50 — удобными массами формы.

Поля гидратации на странице нет. Гидратация после кормления — строка-результат
рядом с честным указанием, от чего считали: от последней сохранённой или, если
её нет, от стартовой 50% из буклета.

«Формуляр кормлений» в дневнике — таблица с прилипающей шапкой
`Дата · Закв. · Мука · Вода · Гидр. · Хранение`; строка целиком помещается в
портрет, пустая гидратация старой записи показывается как «—» и объявляется
«не указана». Длинная заметка, комментарий и фотокарточка раскрываются
отдельным действием под строкой. История едет через `LazyColumn` целиком,
без потолка в десять строк.

«Следующее кормление» — точный местный момент («Следующее кормление:
19 августа, 08:30»), одинаковый на первой полосе и в дневнике. Слова
«примерно» в книге больше нет.
