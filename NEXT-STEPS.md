## Правила для автономного агента

- Продолжай с первой невыполненной задачи `[ ]` сверху вниз. Дошёл до конца —
  останавливайся, не выдумывай новые этапы сверх того, что здесь и что явно
  вытекает из уже начатого пункта.
- Коммить после **каждой** выполненной задачи (`git add -A && git commit`).
  Перед коммитом с изменениями в Kotlin: `./gradlew testDebugUnitTest`
  (эмулятора на этой машине нет — `androidTest`/инструментальные тесты здесь
  не запустить; для визуальной проверки экранов используй Paparazzi/Roborazzi,
  см. Этап 2).
- Отмечай `[x]` только когда задача реально сделана и проверена, не заранее.
- **Не гадай.** Если в ходе задачи всплывает настоящая продуктовая
  неоднозначность, которую нельзя безопасно закрыть по DESIGN-V4.md,
  README-CYCLE0.md или истории git — не придумывай ответ и не трогай визуал
  на свой вкус. Опиши находку в разделе «Открытые вопросы» внизу этого файла
  (что именно неоднозначно, где в коде/доке, какие варианты видишь) и переходи
  к следующей задаче.
- Учти: экраны 5 (Кормление), 6 (Готово), 7 (Уведомления), 8 (Настройки) в
  DESIGN-V4.md явно помечены «мокап — на согласовании» — расхождение кода с
  DESIGN-V4.md там всё равно баг (описание в доке считается текущей истиной),
  но самовольно менять визуал за пределами написанного в доке нельзя — это
  тоже повод для «Открытых вопросов», а не для импровизации.
- Никогда без явного запроса: `git push`, изменение release signing config,
  изменение `versionCode`/`versionName`, правки содержания DESIGN-V4.md
  (решения по дизайну — за Димой/Полиной, не за агентом).

### 2026-07-21, Задача 1.2: заголовок `RecipeDetailScreen` без «СТР. N»

DESIGN-V4.md §«Экраны»/2 описывает заголовок разворота как
«РЕЦЕПТ № NN · СТР. N» — номер рецепта **и** номер страницы книги.
`RecipeDetailScreen.kt` (`PageLabel("Рецепт № %02d".format(chapterIndex))`,
строка ~82) рисует только номер рецепта, без «· СТР. N». В модели данных
(`Recipe`, `recipes.json`) понятия «номер страницы» вообще нет — его неоткуда
взять, не выдумав алгоритм пагинации (сколько «страниц» занимает рецепт:
фиксировано? зависит от длины текста/шагов?). Это решение продукта, не то,
что можно безопасно угадать по коду. Варианты: (а) ввести фиксированную
нумерацию страниц по порядку рецептов в книге (глава = страница, тогда
«· СТР. N» дублирует «№ NN» и, возможно, не нужен вовсе); (б) считать
страницы по объёму контента (шаги + ингредиенты) — сложнее, требует
согласования формулы; (в) убрать «· СТР. N» из DESIGN-V4.md как
неприменимое к текущей архитектуре данных. Решение — за Димой/Полиной.
