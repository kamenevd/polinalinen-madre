# ADR-0005: Dormant shelf and membership ledger

- **Status:** Accepted
- **Date:** 2026-08-20

## Context

`POST /api/madre/family/leave` удалял запись `families`, когда уходил последний
участник. Это делало возврат по старому коду невозможным и оставляло исторические
`bake_stats` с relation на уже несуществующую полку.

Требование Cycle 28: «полка переживает уход последнего», а спящую полку может
оживить только бывший участник. Для этого серверу нужна durable запись прежнего
членства, которая:

- появляется при `create/join`, а не при первой выпечке;
- переживает `leave`;
- не даёт доступ сама по себе.

`users.family` не подходит для памяти о прошлом: это живой ACL и после ухода
обязан быть пустым. `bake_stats` тоже не подходит: у участника без выпечек там
нет следа.

## Decision

1. Уход последнего больше не удаляет `families`: полка засыпает с тем же
   `invite_code_hash` и той же статистикой.
2. Добавляется закрытая коллекция `family_members` с уникальной строкой на пару
   `(family, user)` и статусом `active/left`.
3. `create/join/leave` пишут журнал в той же транзакции, что и `users.family`.
4. `join` в спящую полку разрешён только при наличии строки журнала для пары
   `(family, user)`.
5. При оживлении спящей полки владелец становится вошедший бывший участник, а
   старый код приглашения гасится ротацией хэша.
6. ACL по-прежнему строится только на `users.family`; `family_members` остаётся
   закрытым (`list/view/create/update/delete = null`).

## Consequences

- Возврат на свою полку возможен даже после ухода последнего.
- Полка может копиться в состоянии «спящая»: автоматической сборки таких записей
  нет, пока не принята отдельная политика хранения чужой статистики.
- Посторонний со старым кодом не получает историю спящей полки.
- Откат миграции `family_members` удаляет журнал и лишает спящие полки доказуемого
  прежнего членства (fail-closed: оживление станет недоступным).
