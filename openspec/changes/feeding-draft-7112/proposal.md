# Черновик кормления в Дневнике · 7.1.12 (65)

## Зачем
SCREENS-7.0.3 §4 F4: закрыть изменённую форму без окна; вернуть черновик при повторном открытии, но не после выхода из Дневника.

## Доказанный дефект
На неизменённом production f87d7cfc87529e4b64c4a8e267827d302fba8973 два Compose-теста с настоящим MadreNavHost проходят Дневник → кормление → кнопка закрытия / системный Back → открыть. Оба теряют незавершённый ввод муки 137 и заметку. Более того, popUpTo(Home) удаляет сам Дневник. Исходный красный JUnit, log и пустой production diff: `/root/.hermes/work/madre-feeding-draft-evidence-20261026/red-*`.

## Изменение
Сохраняем настоящий NavBackStackEntry формы через штатные Navigation saveState/restoreState, а не копию нескольких полей. Дневник остаётся его настоящим родителем. Слот ограничен id посещения Дневника и реальными userId/configId. Выход из Дневника, смена владельца и успешная запись очищают слот. Ошибка не очищает. Прямой вход и уведомление сохраняют прежний Home-parent и не создают второй экземпляр формы.

## Приёмка
Настоящая навигация кнопкой и Back, незавершённый точный ввод, выбранный пресет, массы, место, дословная заметка, настоящая synthetic-gallery цепочка с проверкой файла и байтов. Восстановление при закрытой форме, поздняя Room-история, ошибка/повтор/успех, запрет выхода при Saving, очистка при выходе из Дневника и смене настоящих владельцев. Existing feeding/nav/data assertions сохранены. Style boundary, debug/release compile и исполненные focused unit/Compose.

## Исправления единственного ревью
На неизменённом production `ca0d272f95555624971289e8534e0637cbb1cc47` семь новых реальных NavHost/Room-регрессий красные (`fix-red-receipt.json`, `fix-red-junit`, `fix-red.log` в том же evidence-каталоге). Результат сохранения привязан к id записи навигации и saveable-поколению формы, а не только владельцу: старые Success/Error после A → B или A → B → A потребляются без закрытия/очистки нового черновика. Общий Saving по-прежнему блокирует выход и второе сохранение. История фильтруется по текущему configId до расчёта масс, пресета, суммы и предыдущей гидратации. Test-only задержка настоящего Room executor доказывает отсутствие заимствования истории A и последующую инициализацию из B, сохраняя ручной и восстановленный history fence.
