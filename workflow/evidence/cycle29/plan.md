## Principal, consent and OAuth contract
Optional Dialogs authorization-code linking approved on the owned phone; not a new family-account login. Full Yandex ID sign-in in Madre is not needed for this installation-scoped capability. No email merge, no family/account/PB token sent to bridge or accepted by any voice endpoint. Existing local/offline/family identity preserved.
Android creates dedicated random256-bit installation credential in Keystore-encrypted storage (allowBackup=false); enrolls over TLS only after consent. Server returns random installation ID, stores credential hash. Installation is a narrow cryptographic capability, never device_id/person identity. Only installation credential can upload snapshot, open long-poll, submit phone receipt/ack, disconnect or approve pairing. OAuth bearer cannot impersonate phone, poll, upload or ack success. OAuth bearer can only read/enqueue for its bound bake+grant. Other credentials are rejected.
Server-only client id/secret in protected config and exact Dialogs console (no secret APK). Allowlist exact redirect https://social.yandex.net/broker/redirect, response_type=code, configured scope value bake:read&bake:control. Redirect parameters code, state, client_id, scope: preserve received state/client_id/scope values exactly, with only normal URL percent encoding. Do not normalize/reorder/split-and-rejoin scope. Hashed one-use code60s; access15min; hashed rotating refresh with replay revocation and max30days. Token/refresh response under5000 chars, each token under2048 chars, expires_in integer; refresh completes within5s. Never log tokens, codes or full URI; raw access/refresh tokens never in URLs. The required one-use authorization code redirect is the sole protocol exception, not permission to log it.
Browser authorize GET renders entry page; POST with CSRF creates pending5min challenge, protected originating browser cookie (Secure/HttpOnly/SameSite=Lax). Browser shows10-character alphabet32 code. It is typed ONLY into Madre phone screen, NEVER spoken to Alice; skill rejects code utterances. Authenticated phone resolves code, shows exact requested scope+selected bake and shared-Station warning, then second explicit approve binds challenge. Browser cookie+CSRF confirmation required to issue one-use code. Per-IP/installation attempt caps and rate limits, generic wrong/expired denial; no GET mutation.
Grant binds exact installation, explicitly selected bake UUID and selection generation. Never auto-select, even a single bake. Recipe+step and duplicate-bake distinguishing identity visible during selection. Switching bakes revokes and requires re-link; no last-writer-wins/user_id replacement across devices. One Yandex account shares token across surfaces; token does not identify speaker. Explicit consent: anyone near shared Station can control only the selected bake. No starterName/account/location/photos/diary/other bake data in snapshots.
Disconnect clears selection+consent/generation locally immediately, stops poll, sends revoke; offline shows pending-server-revoke, rejects locally while lease expires remotely. Existing family signout also disconnects locally for privacy without account merge. Grants expire/revoke; grant existence alone is not connected status.
Only send start_account_linking if meta.interfaces.account_linking exists; never include response alongside it. account_linking_complete_event lacks command: verify token, optionally read status, NEVER enqueue or replay saved mutation. Conflicting bearer in header/body rejects.

## Voice interaction / dispatch
Read-only queries: what cooks/current/repeat/remaining/next contents/known quantities. Что дальше reads, never advances. Strict bounded input, no arbitrary natural-language action inference. Initial controls PAUSE/RESUME/ADVANCE/BACK/CANCEL; no time-adjust action not already modeled.
Confirmation is TWO TURNS/TWO OBJECTS. Turn1 stores only server pending intent (operation, recipe, step, bake UUID, revision, generation, session), TTL30s; speaks exact target and question; immediately ends webhook. No phone command minted/enqueued. Later confirmation revalidates same pending intent/current snapshot/revision. Only then mint UUID phone command with4s delivery expiry, begin <=2s ack wait inside total4.5s platform budget. Bound pending intent to same authenticated grant/session, clear once consumed. Expired/changed intent not sent.
Bare да confirms only pending non-cancel intent, never advances alone. Cancel requires exact подтверждаю отмену and only pending CANCEL. That phrase never confirms pause/advance/back. стоп/выход/хватит/bare отмена clears intent and exits skill, never cancelSession. Last-step voice ADVANCE returns PHONE_REQUIRED, must NOT call advance(), completedAt, startRecordInsert, finish/share/photo/record. Explain finish on phone; existing phone Готово remains local path.
Command fields: UUID, bound grant/selection generation, bakeKey, expected revision/step/paused state, operation, expiry and live connection generation. Delivery only on current lease; never reconnect replay. Phone validates identity, consent, generation, revision and time/skew before transaction. Insane clock skew fails closed, cannot extend TTL. Success exclusively actual durable phone receipt+state. Before enqueue/dispatch rejection says не отправлено; after enqueue/dispatch without ack says результат неизвестен, проверь телефон. Later query may read stored receipt but cannot resend action. Never call unacknowledged action success or unchanged. Timing is clamped timestamped phone snapshot projection, freshness max6s, not server timer.
