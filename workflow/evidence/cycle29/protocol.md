## Credentials and endpoints
Phone authentication: Authorization: Installation <256-bit credential>, never Bearer. Credential is generated on phone as32 random bytes base64url without padding. Server stores hash only; JSON enrollment body has credential. OAuth access/refresh are independently random prefixed capabilities; installation credential cannot be used as bearer or vice versa. Exact OAuth redirect https://social.yandex.net/broker/redirect; scope value bake:read&bake:control preserved from request. Environment defines OAuth client id+secret. PB tokens never accepted.
POST /phone/enroll {credential} -> {installation_id}. Idempotent for same credential; rate/cap bound. No bake/user data until explicit consent/selection.
POST /phone/select {bake_key, selection_generation} -> {selected:true}; installation-only. bake_key UUID, generation UUID generated by phone. Changing either atomically revokes previous grants/intents/commands/snapshots. No other device affected. Not a linkage claim.
POST /phone/disconnect {} -> {revoked:true}; revoke installation grants and selected bake/leases, keep installation credential for deliberate later enrollment/selection. Works idempotently.
POST /phone/pair-preview {code} -> {scope, expires_at, challenge_id}; no mutation grant; requires installation + currently explicit selection.
POST /phone/pair-approve {challenge_id,code,bake_key,selection_generation} -> {approved:true}. Second explicit consent on phone. Bind selected bake immutably; only originating browser may exchange challenge to OAuth auth code.
POST /phone/poll {connection_id,selection_generation,snapshot} -> {server_time,linked,command:null|command}. Snapshot always from canonical controller, polls max1s to fit current proxy3s. Same connection UUID for lifetime FGS controller registration; first/new connection kills old pending delivery, never replays. Freshness6s from server receipt, snapshot device time sanity. linked=valid unexpired grant for selected bake, not mere enrollment. Live lease only while polls current. No resurrection old commands.
POST /phone/ack {connection_id,selection_generation,command_id,bake_key,expected_revision,status,new_revision} -> {accepted:bool}. INSTALLATION-ONLY, match exact dispatched command, connection+generation+bake+expected rev. status APPLIED/STALE/EXPIRED/REJECTED/PHONE_REQUIRED. APPLIED only after actual phone Room commit; server cannot synthesize. Ignore invalid/late new command ack; late authoritative receipt for dispatched command may settle UNKNOWN, never requeue. Retain receipts24h for reads. Return HTTP denial on OAuth Bearer at ALL phone routes.

Null recipe_revision or unknown portions=>control_ready=false; no trusted quantities or scaled step texts. No server rescale. ## OAuth browser
GET /oauth/authorize validates exact client/redirect/response_type/scope, renders no-mutation CSRF start form; POST creates originating-cookie challenge code10 chars alphabet32, TTL5min. No CORS, CSP no external scripts, no-cache/referrer/frame ancestors. Browser polls authenticated challenge via same cookie; after phone consent second browser POST+CSRF issues one-use60s code and303 redirect preserving state/client_id/scope. GET never grants. All arbitrary redirects rejected before rendering. Token POST /oauth/token (form-urlencoded, client credentials+authorization_code+redirect_uri or refresh_token) and /oauth/refresh support documented OAuth flow; responses <5000chars, tokens<2048, expires_in int900. Refresh rotation/replay detection; max30day grant, hash tokens/code at rest. No full URL logs (auth-code exception solely required redirect).
